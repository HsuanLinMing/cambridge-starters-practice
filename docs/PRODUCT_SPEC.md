# Product Spec

## 產品定位

**Cambridge Starters Practice 是本機自用工具，不是正式上線產品，也不是商業服務。**

明確用途：

1. **給自家小朋友 Cambridge Starters 考前練習**——這是首要、且唯一的「使用者價值」目標。
2. **練習 Claude Code CLI / Codex AI 協作開發流程**——這是工程目的；專案同時作為 AI CLI 開發的試驗場。

明確邊界：

- 第一版**不部署、不上線、不公開服務**，只在本機跑（`npm run dev` / `npm run build` 自用）。
- 第一版**不做商業化、不做付費、不做會員系統**。
- 資料優先以**本機 JSON / 本機素材**為主，不接後端、不接資料庫、不接雲端同步。
- 考完後**可能不再長期維護**——因此設計與實作優先追求「考前實用」，不追求「完整商業產品規格」。

當功能取捨出現拉扯時（例如：要不要為了「未來上線」加抽象層 / 加帳號系統 / 加多人權限），**一律往「本機自用、考前實用」靠**，遠離「正式產品化」。

### 第一階段使用方式：Mac 本機 + 平板同 Wi-Fi

實際使用情境是這樣：

- 在 Mac 本機啟動 Next.js dev server（`npm run dev`）。
- 平板（iPad）與 Mac 連到**同一個 Wi-Fi**，用 Safari 開 Mac 的區網 IP（例如 `http://192.168.x.x:3000`）。
- iPad Safari 可從分享選單「加入主畫面」，讓小朋友像 App 一樣開啟。
- 操作細節見 `README.md` 的「在平板上使用（同 Wi-Fi 區網）」一節。

選擇此方式而**不部署 Vercel** 的原因：

- 未來可能會放官方 sample / 歷屆考題素材，平板 + 本機區網即可使用，避免素材外流。
- Vercel 等公開部署**只保留為未來可選方案**，前提是不放官方素材或全部改用自製 / 可公開素材。
- 第一階段不改 Flutter、不打包 App、不做行動 App 包裝。

## 使用者

主要使用者：1 位（自己 / 家中小孩），其中**包含國小一年級小朋友**。

特性：

- 中英對照需求高（介面繁體中文，題目英文）
- 需要清晰的圖片、簡單的發音
- 單機、一個人用；沒有多人、權限、登入需求（見「目前明確不做」）

## 國小低年級使用者設計原則

因為主要使用者包含國小一年級的小朋友，UI / UX 必須以小一可獨立操作為前提。所有 P2 之後的畫面都要符合下列原則：

- **操作簡單直覺**：核心動作（看單字、播發音、切分類）一兩步可完成，不要藏進選單。
- **步驟少**：避免多層導覽。一個畫面盡量只做一件事。
- **按鈕大、明確**：可點區域至少 56×56 px 等級，配對應 emoji 或圖示輔助辨識，不要只用文字。
- **色彩明亮、童趣、親和**：以淡色系為主（例如淡黃、淡藍、薄荷綠、粉紅），避免成人感重的深色或冷灰色。
- **學習以圖片為主**：每個單字盡量都搭配圖片；圖片區應佔卡片主要視覺位置。
- **發音播放是重要輔助**：發音按鈕要明顯、好按；按下後要有立即視覺回饋。
- **圖片 / 音檔 fallback 要溫和**：素材不存在時，畫面不可壞掉；用色塊、首字母或「準備中」字樣處理即可。
- **文字節制**：畫面上不要塞長段說明；提示用一句短句即可。
- **不做複雜遊戲化與大量動畫**：避免分散小一的注意力，也避免增加維護成本。
- **不做翻牌、拖曳等需精細手勢的互動，除非任務明確要求**。

這些原則優先級高於「視覺豐富度」「資訊密度」之類的成人慣例。當兩者衝突時，以小一可操作為準。

## 主要功能（願景）

`/review` 與 `/quiz` 的分工要清楚——**不要混為一談**：

- **`/review` 複習區（複習中心）**：分項能力練習。一張卡片一種能力，一次只練一件事。
- **`/quiz` 測驗區**：完整考卷、歷屆 / sample 題、AI 仿真題、交卷評分、錯題講解。模擬考級別的整份考卷體驗。

考題練習不再列為複習中心的主入口卡片；複習中心可在底部放一個小型輔助提示連到 `/quiz`，但視覺層級低於 5 張主卡片。

### 複習區（`/review`）：5 個主入口

- **單字複習**（`/review/words`）：A~Z 單字、圖片、發音、看答案翻牌。已實作為主流程。
- **看圖練習**（`/review/picture`）：兩種方向都已實作——「**看圖選英文** 4 選 1」與「**看英文選圖** 4 選 1」，頁面頂部用 tab 切換、預設看圖選字、切換時自動回到第 1 題。圖片缺檔有 fallback、答對 / 答錯即時鼓勵回饋、「下一題」循環。第一批 10 個自製 SVG 已接入（apple / cat / dog / book / red / blue / one / two / mother / father），其餘單字仍 fallback；後續補圖屬 P2-4C-2B-2。**這是分項複習，不做分數保存、不做交卷、不做 localStorage**——那些屬於 `/quiz` 測驗區範圍。
- **聽力練習**：聽單字、聽句子、選圖片。規劃中。
- **句型練習**：常見句型（`This is...` / `I can see...` / `There is...`）。規劃中。
- **位置 / 顏色 / 數量**：介系詞（`in / on / under`）、顏色 + 名詞（`red ball`）、數字 + 名詞（`three apples`）。規劃中。

複習中心首頁底部可放一句**輔助提示**（如「想做完整考卷？請到測驗區。」），引導使用者前往 `/quiz`，但不作為主入口卡。

### 測驗區（`/quiz`）

- 多種題型：Multiple choice / Listening / Matching / Fill-in-the-blank
- 即時對錯回饋 + 結算頁
- 完整考卷 Session、交卷評分、錯題紅色標示、簡單講解、再練習錯題
- 詳細方向見下節「測驗與考前練習方向」

### 模擬考

- 完整題組（Listening 部分 + Reading & Writing 部分）
- 計時器與一次性批改

### 進度記錄（本地）

- 答對率、最近練過的單字、錯題回顧

**單字複習只是 `/review` 的其中一個入口，複習區的長期目標是涵蓋 Cambridge Starters 各種分項能力練習**。詳細項目對照「複習內容擴充方向」一節，實作排程見 `PROJECT_ROADMAP.md`。

## 複習內容擴充方向

複習區的內容不只 A~Z 單字，後續會逐步擴充為下列幾類，覆蓋 Cambridge Starters 常見出題範圍：

- A~Z 單字（已實作主流程）
- 主題單字（colors / animals / food / family / school / home / weather / actions …）
- 常見句型（短句模板：`I have a ___.` / `This is my ___.` / `Where is the ___?`）
- 介系詞（`in` / `on` / `under` / `next to` / `behind` 等位置詞）
- 顏色 + 名詞（`a red apple` / `a blue pen` 等組合）
- 數字 + 名詞（`one cat` / `two dogs` 等單複數搭配）
- 看圖問答（看圖回答 What / Where / Who / How many）
- 聽力指令（`Point to the ___.` / `Colour the ___ ___.`）
- 簡單拼字與名字辨識（拼字練習、英文姓名常見字）

實作順序由 P2-4 / P3 / P4 各階段決定，本節僅列出方向，不直接對應某一輪任務。

## 單字複習主流程

「單字複習」是複習中心其中一個入口，主要動線為 **A~Z 字母 → 字母總覽 → 單字詳情**，貼近 Cambridge Starters 單字表的學習方式，也適合小一直接從字母切入。

進入點：`/review` 複習中心首頁的「📖 單字複習」卡片。

1. `/review/words`：A~Z 字母入口。每個字母顯示該字母目前有幾個單字。
   - 有單字的字母可點擊。
   - 沒單字的字母淡化 / disabled，不可點。
2. 點某個字母（例如 A）後進入該字母總覽頁 `/review/letter/a`。
   - 列出該字母開頭的所有單字，類似單字表清單，可多欄排列。
   - 每個單字可點擊，進入單字詳情頁。
   - 若該字母沒有單字（理論上不會走到這條路），顯示溫和提示與返回 `/review/words` 的按鈕。
3. 點某個單字（例如 apple）後進入單字詳情頁 `/review/word/apple`。
   - 大圖區、大字體英文單字、發音按鈕。
   - **詳情頁採「翻牌 / 看答案」互動**：中文意思、英文例句、中文例句**初始隱藏**，讓小朋友先看圖與英文回想，再按「🔍 看答案」翻開；翻開後可按「🙈 再想一次」收起。
   - 圖片缺檔顯示首字母 +「圖片準備中」，音檔缺檔或播放失敗顯示「音檔準備中」。
   - 上一個 / 下一個依**整體 A~Z 單字順序**前進；某字母最後一個單字按下一個會接到下一個有單字的字母的第一個單字。第一個單字的「上一個」、最後一個單字的「下一個」皆 disabled。切換到新單字時，翻牌狀態會自動回到「收起」。
   - 提供「回到 X 總覽」按鈕。

主題分類（food / animals / colors …）相關的元件與 helper 仍保留在程式碼中，但**不作為目前 `/review` 主入口**，定位為**未來的補充模式**（例如「以分類複習」「以情境複習」），需要時再啟用。

## 測驗與考前練習方向

本專案不只做單字複習，**測驗區的長期目標是支援 Cambridge Starters 的考前練習**。本節定義方向，實作排程見 `PROJECT_ROADMAP.md` 的 P3 章節。

### 題目來源策略

題目來源會逐步加入下列三種，並在資料中明確標記：

| 標記 | 說明 |
| --- | --- |
| `official_sample` | 官方公開的 sample papers / 樣題整理出的題目 |
| `past_paper` | 歷屆考題整理（僅供自家學習使用，不對外散布） |
| `ai_generated` | 由 AI 依題型風格生成的仿真題 |
| `custom` | 使用者自製或老師補充的題目 |

每一題在 JSON 中至少帶 `source` 一個欄位，以便日後篩選練習範圍（例如「只練 sample papers」「只練 AI 仿真題」）。

### AI 仿真題

不依賴官方版權素材，重點是讓 AI 依 Starters 題型與風格生成可大量練習的題目：

- **題型對齊**：依 Starters 實際題型出題，包含 Listening 與 Reading & Writing。
- **風格對齊**：小一友善、可愛、活潑、清楚；不追求刁鑽。
- **內容適合初學英文兒童**：避免冷僻字、複雜句構、文化背景過深的情境。
- **目標是建立信心與題型熟悉度**，不是測難度。
- 同步輸出 **TTS script**（給 listening 題目產生音檔）與 **image prompt**（給看圖題目產生插畫）。
- 每一批生成都記錄 prompt 版本，方便回溯出題品質。

### 題型清單（第一版範圍）

第一版會優先實作下列題型，皆可由 sample / past paper / AI 任一來源供題：

- Listening：
  - 聽音選圖
  - 聽句子選答案
  - 聽指令做動作（簡化版）
- Reading & Writing：
  - 看圖選字
  - 選字填空（給選項）
  - Matching / 連連看
  - Fill in the blanks（自由填空，不區分大小寫）
  - 簡單拼字（看圖拼字）

### 素材策略（音檔 / 圖片）

- 音檔：
  - 第一階段優先使用 **TTS 自製**（macOS `say` / Web Speech / 雲端 TTS 都可）。
  - 也可由使用者手動把現成音檔放入 `public/audio/` 對應路徑。
  - 不下載官方音檔。
- 圖片：
  - **第一階段優先使用自製簡單 SVG 圖像**（純 shape / path / circle / rect 組成，不需精緻；統一 `viewBox`，色彩柔和）。SVG 與 PNG 在 `<img>` / `new window.Image()` 載入行為一致，既有 fallback 機制無需修改。
  - 也可使用使用者手動整理的本機素材、歷屆題自繪重畫、或 AI 自製插畫。
  - **嚴禁**：不下載 Cambridge 官方圖片、不下載歷屆考題圖片、不使用網路抓圖或爬蟲、不使用有版權風險的外部素材。
  - 缺圖時 `<PracticeImage>` / `<VocabularyCard>` 自動 fallback 為「首字母 + 圖片準備中」（`/review` 是分項複習區，缺圖不影響練習可進行）。
  - color 類單字（red / blue / green …）的圖片**不要在圖片內放單字英文**，避免看圖選字題型直接洩漏答案；用純色塊或顏色物件即可。
- 資料補入流程（**第一階段不做自動爬蟲**）：
  - 設計 `source_materials/`（或類似名稱）資料夾，使用者手動把 PDF、圖片、音檔、整理後文字放進去。
  - 後續系統提供轉換工具：把整理後文字 / CSV 轉成 `data/quizzes.json` 或對應 schema 的本機 JSON。
  - 使用者整理過程不上雲、不上後端。

### 完整考卷 Session

測驗區的核心使用單位**不是單題練習，而是「一份完整考卷」**——對齊 Cambridge Starters 真實考試的結構，也讓小朋友習慣「從第一題做到最後一題」的節奏。

#### Session 概念

- **一次生成一整份完整考卷**（相對於「一次只給一題」的隨機刷題模式）。
- 一份考卷可包含多種題型混合：
  - Listening
  - Matching / 連連看
  - Fill in the blanks / 填空
  - 看圖選字
  - 看字選圖
  - 選圖題
  - 選字題
- 考卷題目可**混合來源**（依「題目來源策略」表格）：`official_sample` / `past_paper` / `ai_generated` / `custom`，同一份考卷內可同時包含多種來源。
- **第一版不計時**。未來如要支援模擬考計時，**設為可選功能、預設關閉**，避免時間壓力嚇到小一。
- 一份考卷在進行中視為一個「Session」：有唯一識別碼、有作答狀態、有可恢復的進度。
- 流程仍受「國小低年級使用者設計原則」約束：題目敘述短、選項少、操作步驟少、低壓力。

#### 作答進度保存（localStorage）

小朋友會做到一半離開（吃飯、洗澡、睡覺），下次進來要能**繼續做原本那份考卷**。

- 第一版**不做登入**，因此保存方式以**瀏覽器 localStorage** 為主。
- 因為主要使用者是 1 個人、在自己慣用裝置上練習，本機 localStorage 在此情境下足夠（不需要後端、資料庫或雲端同步——見「目前明確不做」）。
- localStorage 至少保存以下欄位（**詳細 schema 由 P3-1 實作時定案**）：

  | 欄位 | 說明 |
  | --- | --- |
  | `examSessionId` | 該次考試的唯一識別碼 |
  | `examPaperId` | 對應的考卷模板 id（決定考卷題目組成） |
  | `questionOrder` | 題目順序（生成時打散的順序，恢復時要一致） |
  | `answers` | 每題作答內容（題 id → 使用者選的選項 / 填的字） |
  | `currentIndex` | 目前進度（做到第幾題） |
  | `submitted` | 是否已交卷（boolean） |
  | `score` | 交卷後分數（未交卷時為 null） |
  | `wrongQuestionIds` | 答錯題目 id 清單（交卷後填入） |

- localStorage 一筆 = 一個 Session；同一個 `examPaperId` 可重新測驗產生**新的 Session**（保留舊 Session 直到使用者選擇刪除或被覆蓋）。
- 換瀏覽器或清掉 localStorage 即等於重設進度，不視為 bug。

#### 考卷操作

進行中考卷頁面要提供四個明確動作（按鈕大、文字短、不藏在選單裡）：

- **繼續作答**：從 `currentIndex` 接著做下一題。
- **離開這份考卷**：保留進度，回到考卷選擇 / 首頁；下次再進來看到「上次還沒做完」可繼續。
- **重新測驗**：放棄目前 Session 進度，依同一份 `examPaperId` 開新 Session（題目順序可重新打散）。重新測驗前要顯示確認提示（避免誤觸）。
- **直接交卷**：未答題視為未作答（不強迫小朋友寫滿），立刻進入交卷評分。

#### 交卷與結果頁

交卷後立即顯示結果頁。設計原則仍是**鼓勵 > 懲罰**：

- **計算分數**：正確題數 / 總題數，顯示「答對 N 題 / 共 M 題」與簡單百分比或星星等鼓勵性視覺。
- **錯誤題目用紅色標示**（紅色僅代表「這題要看一下」，不是責備）。
- **顯示正確答案**：每題明確標示哪個選項才是對的。
- **顯示簡單講解**：每題附一句簡短說明（為什麼選這個答案；用小一聽得懂的語氣）。
- **講解語氣小一友善**：避免「你錯了」「不對」這類字眼，多用「正確答案是 ___」「下次可以注意 ___ 唷」。
- **「再練習錯題」入口**：結果頁提供按鈕，可把錯題撈出來再做一次，作為後續功能（屬 P3-6 之後的延伸）。

### 與小一設計原則的關係

「測驗與考前練習方向」所有題目都仍受「國小低年級使用者設計原則」約束：

- 題目敘述短、字級大、選項少（建議每題 2~4 選項）。
- 每題畫面一次只呈現一個動作（看 → 選 → 下一題）。
- 答錯不懲罰，鼓勵性回饋；答對給簡單視覺正向回饋（不需大量動畫）。
- 第一版測驗區**不計時**；未來若加入模擬考計時，預設關閉，避免時間壓力嚇到小一。

## 長期目標：自家仿真 Starters 模擬考系統

本專案的長期方向是逐步打造**接近真正 Cambridge Pre A1 Starters 的自家模擬考系統**——讓孩子在考前能熟悉完整考試流程，包含 Listening、Reading & Writing、Speaking 三大段。

長期目標仍在「**自家 / 家中練習**」場景下使用，**不公開、不商業化、不偽稱官方**。實作排程見 `PROJECT_ROADMAP.md` 的 P3-7 / P3-8 / P3-9（正式題型模板化）+ P4（Speaking Examiner Agent）+ P5（完整仿真考試體驗）。

### 設計原則

- **目標**：自用 / 家中練習 / 熟悉考試流程，**不是商業考試模擬器**。
- **對齊正式考試體驗**，但**不使用官方受版權素材**。
- **題目以自製 / AI 仿真 / 人工審核為主**：所有題目都會走「先草稿 → 審核 → 進正式 JSON」流程（見 P3-3 / P3-8）。
- **官方資料只作為題型結構與 wordlist 參考**：不複製官方原文、不重製官方圖片 / 音檔（見 P3-7 與 `source_materials/README.md`「官方資源與歷史題整理原則」）。
- **Speaking 會以 TTS + 錄音 + AI 回饋模擬**（P4），但**所有 AI 評分只是練習建議**，不是官方成績。
- **AI 評分與「目前明確不做」邊界相容**：客觀題的 AI 評分仍不做（以資料中的 `answer` 比對為準）；Speaking 屬開放式回答，AI 提供的是**鼓勵性練習回饋**——定位是「練習建議 / 不是考試評分」，UI 處處標示。

### Speaking Examiner Agent

Speaking 模擬考官**不是單次呼叫 AI 評分**，而是設計成一個 **Speaking Examiner Agent（口說考官代理）**——agent-based flow，有狀態機、有回合控制、有考官台詞、有評分規則。

核心設計：

- 扮演 Cambridge Starters 口說考官，以**友善鼓勵**語氣帶小朋友走完 Speaking Part 1~4。
- **小孩不是單次丟一句回答給 AI**，而是由 Agent 帶著完成整個流程。
- Agent 透過 TTS 扮演考官語音；小孩透過麥克風錄音回答。
- 系統將錄音透過 STT 轉文字後，交給 Agent / 評分器分析。
- Agent 可根據回答做**簡單追問**或**進入下一題**——非無狀態單句批改。
- Agent 內部狀態（每個 turn）至少含：`currentPart` / `currentQuestionIndex` / `examinerPrompt` / `expectedAnswerType` / `childResponse` / `transcript` / `feedback` / `score`（pronunciation / vocabulary / response relevance / confidence 觀察點）/ `nextAction`。
- 每一回合的 part / examiner prompt / TTS script / child audio / transcript / AI feedback / score 都會保存於 localStorage（**不上雲、不上後端**）。
- 回饋必須**小朋友友善、以鼓勵為主**，不糾正細節文法錯誤——以「能溝通」為合格門檻。
- **AI 分數只能作為練習回饋**，不是 Cambridge 官方成績。
- UI 必須清楚標示「**AI 練習回饋，非官方考試分數**」（出現在每個評分畫面）。
- **不做 Cambridge 等級對應宣稱**（不寫「相當於 Pre A1 / A1 / A2」之類）。

Agent 的目標是**模擬考官互動流程**，讓孩子練習「聽懂指令 → 回答問題 → 維持簡短對話」的能力，**而不是只做單句英文批改**。

詳細實作規劃見 `PROJECT_ROADMAP.md` 的 P4-1 ~ P4-9。

### 完整仿真考試體驗（P5）

把 Listening + Reading & Writing + Speaking 串成一份完整模擬考：

- TTS 考官貫穿全流程；Speaking 由 Examiner Agent 接管。
- 成績紀錄、家長檢視、弱點分析、錯題與口說弱點複習皆走本機 localStorage。
- 仍維持「**不上雲、不上線、不做帳號、不做雲端同步、不做付費**」（見「目前明確不做」）。
- 所有 AI 評分一律明示「**練習回饋，非官方成績**」。
- **不做能力等級評定**，不做進度焦慮提示。
