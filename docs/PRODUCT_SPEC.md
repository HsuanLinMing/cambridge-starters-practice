# Product Spec

## 產品目標

打造一個自用的 Cambridge English Starters 複習與模擬考工具。重點不是上架對外、不是商業化，而是：

1. 讓使用者（一位家長 / 老師 / 學習者）能快速複習單字。
2. 用接近真實考試的題型讓學習者熟悉模擬考流程。
3. 過程中記錄下對 AI CLI 協作的開發 workflow。

## 使用者

主要使用者：1 位（自己 / 家中小孩），其中**包含國小一年級小朋友**。

特性：

- 中英對照需求高（介面繁體中文，題目英文）
- 需要清晰的圖片、簡單的發音
- 不需要登入、不需要多人功能

## 國小低年級使用者設計原則

因為主要使用者包含國小一年級的小朋友，UI / UX 必須以小一可獨立操作為前提。所有 P2 之後的畫面都要符合下列原則：

- **操作簡單直覺**：核心動作（看單字、播發音、切分類）一兩步可完成，不要藏進選單。
- **步驟少**：避免多層導覽。一個畫面盡量只做一件事。
- **按鈕大、明確**：可點區域至少 56×56 px 等級，配對應 emoji 或圖示輔助辨識，不要只用文字。
- **色彩明亮、童趣、親和**：以淡色系為主（例如淡黃、淡藍、薄荷綠、粉紅），避免成人感重的深色或冷灰色。
- **學習以圖片為主**：每個單字盡量都搭配圖片；圖片區應佔卡片主要視覺位置。
- **發音播放是重要輔助**：發音按鈕要明顯、好按；按下後要有立即視覺回饋。
- **圖片 / 音檔 fallback 要溫和**：素材不存在時，畫面不可壞掉；用色塊、首字母或「準備中」字樣處理即可。
- **文字節制**：畫面上不要塞長段說明；提示用一句短句即可。
- **不做複雜遊戲化與大量動畫**：避免分散小一的注意力，也避免增加維護成本。
- **不做翻牌、拖曳等需精細手勢的互動，除非任務明確要求**。

這些原則優先級高於「視覺豐富度」「資訊密度」之類的成人慣例。當兩者衝突時，以小一可操作為準。

## 主要功能（願景）

- 單字複習區
  - 主題分類（colors / animals / food / numbers / family …）
  - 單字卡：圖片、英文、中文、例句、發音
- 測驗區
  - 多種題型：Multiple choice / Listening / Matching / Fill-in-the-blank
  - 即時對錯回饋 + 結算頁
- 模擬考
  - 完整題組（Listening 部分 + Reading & Writing 部分）
  - 計時器與一次性批改
- 進度記錄（本地）
  - 答對率、最近練過的單字、錯題回顧

## 第一版 MVP 範圍

對應 `PROJECT_ROADMAP.md` 的 P1–P3：

- ✅ 專案骨架 + 首頁 + 兩個入口
- 單字複習：能瀏覽分類、看單字卡、播發音
- 基礎測驗：能跑完一份小型選擇題測驗並看到分數
- 資料：以靜態 JSON 為準，不接後端
- 範圍刻意縮小，圖片與音檔可先用 placeholder

## 暫不做的功能

下列項目目前不在範圍內，避免 scope creep：

- 帳號 / 登入 / 雲端同步
- 後端 API / 資料庫（Postgres、Supabase 等）
- AI 出題 / AI 評分
- 多語系（除中英以外）
- 行動 App 包裝（先以 web 為主）
- 完整 SEO / 行銷頁
- 付費機制
